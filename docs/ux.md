# Интерфейс Cargo CRM: правила

Главное требование заказчика сверх ТЗ: человек без обучения и без инструкции должен понять, куда нажать и зачем. Интерфейс современный, но без «ИИ-клише». Любая правка интерфейса сверяется с этим документом.

## Кто пользуется и где
- Менеджер по продажам: ноутбук, карточки клиентов и сделки, много переключений между экранами.
- Бухгалтер и руководитель: ноутбук, заявки на оплату, согласование в два клика.
- Кладовщик: телефон или планшет, одной рукой, часто на ходу: приёмка, размещение, остатки.
- Все они не айтишники. Слова системы — слова их работы: «клиент», «заявка», «ячейка», а не «сущность», «запись», «entity».

## Десять правил
1. **Один экран — одна работа.** Заголовок страницы называет работу словами пользователя: «Заявки на оплату», «Принять товар». Не «Treasury», не «Dashboard».
2. **Одна главная кнопка на экране**, всегда в одном месте: на списках справа вверху, в формах внизу. Текст кнопки = глагол + объект: «Создать заявку», «Провести поступление». Никогда «Submit», «OK», «Применить».
3. **Процессы по шагам.** Приёмка и размещение идут мастером с видимым прогрессом: «Документ → Товары → Проведение». На каждом шаге одно действие.
4. **Пустой экран подсказывает.** Нет клиентов — экран говорит «Клиентов пока нет. Добавьте первого» и предлагает ту же главную кнопку. Пустой поиск — «По запросу „…“ ничего не найдено».
5. **Статус — слово в цветной метке**, одинаковое везде: в списке, в карточке, в уведомлении. Цвет дополняет слово, а не заменяет его.
6. **Ошибка стоит у поля** и говорит, что исправить: «Введите 12 цифр БИН», а не «Невалидное значение». Не блокируем кнопку, пока форма не заполнена: нажал — показали, что не так.
7. **Необратимое действие подтверждаем одной фразой с последствием**: «Провести поступление? Остатки на складе изменятся, отменить проведение будет нельзя». Кнопки подтверждения повторяют действие: «Провести», «Отмена».
8. **Иконка только вместе с текстом.** Исключения: поиск, закрыть, меню на телефоне.
9. **Числа и даты по-русски**: «7 ноя 2026», «125 000,00 ₸», количество «12 шт». В таблицах цифры моноширинные (`tabular-nums`), суммы выровнены вправо.
10. **Работает с клавиатуры и на телефоне.** Видимый фокус, Enter отправляет форму, таблицы на узком экране превращаются в список карточек.

## Чего не делаем
- Градиенты, стекло (glassmorphism), фиолетовый, неоновые акценты, эмодзи и «✨» в интерфейсе.
- Декоративные иллюстрации, «приветственные» экраны, анимации появления блоков при загрузке.
- Всё в одинаковых карточках с тенями. Карточка нужна, только если группирует разнородное.
- Заглавные буквы в метках и заголовках (КЛИЕНТЫ), надписи-«бровки» над заголовками, разделители «·» в строках метаданных, стрелки «→» в кнопках.
- Тёмная тема в MVP. Одна светлая тема, сделанная хорошо.
- Выпадающие меню «ещё» с тремя точками для главных действий. Главное действие всегда видно.

## Визуальная система

Опора на предметную область: это рабочий стол бухгалтера и склада. Бумага документов, синие чернила штампа, жёлтые этикетки на стеллажах.

### Цвета
| Роль | Значение | Где |
|---|---|---|
| Фон страницы | `#EEF1F5` | холодный серый, чтобы белые поверхности читались как «лист» |
| Поверхность | `#FFFFFF` | таблицы, формы, карточки объектов |
| Текст | `#1A2130` | основной |
| Текст приглушённый | `#5D6878` | подписи, вторичное |
| Линии | `#D5DBE3` | границы таблиц, полей |
| Главный (чернила) | `#2447C9`, hover `#1C39A6` | главная кнопка, ссылки, активный пункт меню, фокус |
| Этикетка ячейки | фон `#FFD84D`, текст `#1A2130` | адрес ячейки склада везде показывается как жёлтая этикетка `A-01-03` |
| Статус: успех | текст `#176B45`, фон `#DDF3E7` | «Согласована», «Проведено», «Выполнена» |
| Статус: внимание | текст `#8A5A00`, фон `#FFF1CC` | «На согласовании», «Просрочена» |
| Статус: отказ | текст `#A1272B`, фон `#FBE1E2` | «Отклонена», ошибки |
| Статус: нейтральный | текст `#49536A`, фон `#E8ECF2` | «Черновик», «Новый» |

Один цвет акцента. Единственное яркое пятно, кроме главной кнопки, — жёлтые этикетки ячеек. Это и есть «запоминающийся элемент», он взят из реального склада, а не из моды.

### Шрифт
- Одна гарнитура: **Golos Text** (self-hosted через `@fontsource/golos-text`), запасной `system-ui`. Хорошая кириллица, моноширинные цифры, нейтральный характер.
- Размеры: текст 14 px / 20 px; поля ввода 16 px (чтобы телефон не зумил); подписи 13 px; заголовок раздела 20 px / 600; заголовок страницы 28 px / 600.
- Ширина строки текста не больше 70–80 знаков. Формы не шире 560 px.
- Без курсива, без капса, без буквиц. Жирность только 400 и 600.

### Компоновка
```
┌──────────────┬──────────────────────────────────────────────┐
│  Cargo CRM   │  Заявки на оплату            [Создать заявку] │
│              │  [ поиск…            ] [статус ▾] [орг. ▾]    │
│  Главная     │  ┌──────────────────────────────────────────┐ │
│  CRM         │  │ № · контрагент · сумма · дата · статус   │ │
│  Казначейство│  │ ЗО-000124  ТОО Ромашка  125 000,00 ₸ …  │ │
│  Склад       │  │ …                                         │ │
│              │  └──────────────────────────────────────────┘ │
│  Иван П.     │                                               │
└──────────────┴──────────────────────────────────────────────┘
```
- Слева постоянное меню 240 px с четырьмя разделами и именем пользователя внизу. На телефоне меню становится нижней панелью с теми же четырьмя пунктами.
- Содержимое выровнено по левому краю, максимум 1200 px. Ничего не центрируем, кроме экрана входа и пустых состояний.
- Таблицы: строка 44 px, заголовки колонок обычным весом приглушённым цветом, без зебры, разделители тонкие. Клик по строке открывает объект.
- Формы: одна колонка, подпись над полем, поле 44 px высотой, подсказка под полем мелким. Группы полей разделены заголовком раздела, не рамками.
- Скругления: 6 px у полей и кнопок, 10 px у поверхностей. Тени только у всплывающих слоёв (меню, диалог).
- Движение: только в ответ на действие (открылся диалог, раскрылась строка), 150–200 мс. `prefers-reduced-motion` выключает всё.

### Тексты
- Предложения с большой буквы, без точки в кнопках и заголовках.
- Активный залог: «Сохранить изменения», «Отклонить заявку». Одно название действия на всём пути: кнопка «Провести» → уведомление «Поступление проведено».
- Ошибки без извинений и без вины пользователя: что случилось и что сделать.
- Пустые состояния и подсказки короткие, по делу, без восклицательных знаков.

## Готовые компоненты (использовать, а не писать заново)
Лежат в `frontend/src/components/`:
- `PageHeader` — заголовок экрана и единственная главная кнопка.
- `DataList` — таблица на ноутбуке, карточки на телефоне; клик по строке открывает объект; пустое состояние передаётся снаружи.
- `EmptyState` — пустой экран с подсказкой и кнопкой.
- `StatusChip` — статус словом в цветной метке (`ok | warn | bad | neutral`).
- `CellTag` — жёлтая этикетка адреса ячейки.
- `Field` — подпись, поле, ошибка или подсказка.
- `Combobox` — выбор из справочника с поиском (контрагент, товар, ответственный). Список сотрудников: `useUserOptions()` + `toComboboxItems()` из `src/api/users.ts`.
- `ErrorBanner` — ошибка загрузки с кнопкой «Повторить».
- Деньги, количества и даты — только через `formatMoney`, `formatQty`, `formatDate`, `formatDateTime` из `src/lib/format.ts`.
- Уведомление после действия: `toast.success(t('…'))` из `sonner`, текст повторяет действие («Заявка создана»).
- Базовые элементы shadcn/ui в `src/components/ui/`: button, input, label, select, textarea, checkbox, dialog, alert-dialog, table, badge, sheet, separator, skeleton, sonner, command, popover, tabs.

## Проверка экрана перед сдачей
- [ ] Понятно за 5 секунд, что это за экран и что здесь главное действие.
- [ ] Главная кнопка одна и стоит где положено.
- [ ] Пустое состояние и состояние ошибки сделаны и осмысленны.
- [ ] На ширине 390 px ничего не уезжает, кнопки нажимаются пальцем.
- [ ] Статусы и названия действий совпадают с остальной системой.
- [ ] Все строки через `t()`.
